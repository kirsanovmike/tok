# ADR-0001. Строим на Vuetify, без `@tne-ui`

**Дата:** 2026-08-12
**Статус:** принято

## Контекст

`docs/dependecies.txt` перечисляет `@tne-ui/*` — внутреннюю дизайн-систему Трансферы, на которую опирается весь визуал хоста. Проверка показала: пакеты недоступны из среды разработки — `npm view @tne-ui/core` возвращает **404**, `~/.npmrc` отсутствует, реестр дефолтный публичный.

Рассматривались: получить доступ к приватному реестру; строить на чистой Vuetify; написать заглушки `@tne-ui` по угаданному API.

## Решение

Строим на **Vuetify 2.6.3 + SCSS**, ориентируясь на макеты Figma и два скриншота дашборда Трансферы. `@tne-ui` не подключаем.

Места, где в Трансфере стоял бы примитив `@tne-ui`, изолируем в тонкий **слой-обёртку**, чтобы при переносе подменить реализацию точечно.

## Последствия

- Разработка не блокируется отсутствием доступа к реестру.
- Внешний вид может слегка расходиться с продовой дизайн-системой; расхождение локализовано в слое-обёртке.
- Вариант с заглушками отвергнут: выдумывание чужого API вслепую даёт код, который гарантированно придётся переписывать.
- Если доступ к реестру появится, решение пересматривается — замена ограничена слоем-обёрткой.
