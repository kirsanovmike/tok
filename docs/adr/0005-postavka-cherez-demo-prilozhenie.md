# ADR-0005. Поставка через демо-приложение с изолированной папкой компонента

**Дата:** 2026-08-12
**Статус:** принято

## Контекст

Ток должен встроиться в существующее приложение Трансферы, но самой Трансферы у исполнителя нет, а её дизайн-система недоступна (см. [ADR-0001](0001-otkaz-ot-tne-ui-v-polzu-vuetify.md)). Без работающей песочницы невозможно проверить ни оверлей, ни z-index, ни поведение точки входа, ни обе темы.

Рассматривались: npm-библиотека с отдельной сборкой; просто папка исходников; отдельное приложение с демо-хостом.

## Решение

Отдельное **Vue CLI 4.5 приложение**. Внутри:

- `src/tok/` — переносимый компонент. Не импортирует ничего из `src/demo/`, не содержит тестов, внешние зависимости перечислены в собственном `README.md`.
- `src/demo/` — упрощённый дашборд Трансферы как хост: шапка, табы, несколько карточек, футер, переключатель тем.

Тесты живут в корневом `tests/`, вне переносимой папки, чтобы заказчик мог перенести компонент без них.

## Последствия

- Перенос в Трансферу выполняется копированием одной папки.
- Демо-хост даёт честную проверку оверлея, обеих тем и точки входа, но требует поддержки — это осознанная плата.
- Сборка в npm-библиотеку добавляется одним build-таргетом позже, без реорганизации кода.
- Граница `tok`/`demo` проверяема автоматически (grep по импортам) и вынесена в приёмочные проверки плана.
