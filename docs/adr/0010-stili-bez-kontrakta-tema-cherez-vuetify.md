# ADR-0010. Стили без контракта, тема — через Vuetify

**Дата:** 2026-08-25
**Статус:** принято
**Отменяет частично:** [ADR-0009](0009-cveta-i-ustanovka-cherez-tne-ui.md)

## Контекст

ADR-0009 оставил папке Тока три вещи, которые она носит с собой:

1. `styles/_tokens.scss` — функция `tok-color()`, три миксина и полтора десятка
   SCSS-переменных на отступы, радиусы, слои и анимации;
2. `theme/tokens.js` — полную палитру из тридцати цветов;
3. `theme/applyTokTheme.js` — функцию, раскладывающую эту палитру в `--v-tok-*`
   там, где `@tne-ui/core` нет.

Каждая из трёх — обязательство хоста. Партиал обязан попасть в единицу компиляции
**каждого** SFC (`additionalData` в webpack, `preprocessorOptions` в vite): забудешь
— сборка падает на `Undefined function tok-color`. Копия палитры обязана совпадать
с `@tne-ui/core` байт в байт, а расхождение видно только глазами. `applyTokTheme`
— это второй, свой механизм темы рядом с уже стоящим у хоста Vuetify, и его
инлайновые переменные сильнее правил библиотеки: вызвать его в Трансфере значит
сломать переключение темы.

Заказчик потребовал убрать все три: «все стили без переменных и миксинов просто
прописаны в компонентах, theme — только для цветов графика, тему переключает
Vuetify, он и так стоит».

## Решение

- `src/Tok/styles/_tokens.scss` удалён. Вместе с ним — `tok-color()`,
  `tok-button-color()`, `tok-gradient()`, `tok-thin-scrollbar()` и все `$tok-*`.
  Их развернули по месту употребления: цвет пишется как `var(--v-tok-surface)`,
  отступ — как `padding: 16px`, слой — как `z-index: 201`.
- `src/Tok/theme/applyTokTheme.js` удалён. Своего механизма темы у Тока нет:
  переменные объявляет хост, переключает их Vuetify хоста.
- `src/Tok/theme/tokens.js` урезан до цветов графиков — это единственное, ради
  чего значение цвета вообще нужно в JavaScript: amCharts рисует SVG из скрипта
  и `var(…)` не понимает.
- Остальные цвета переехали на сторону хоста. На стенде это `src/demo/theme/tokTokens.js`
  в палитре Vuetify плюс `src/demo/styles/tok-vars.scss`, который переименовывает
  напечатанные парсером `--v-tok-*-base` в те имена, что стоят в стилях. В Трансфере
  ту же работу делает `@tne-ui/core`.
- Имена переменных не изменились: `--v-tok-<токен>`, без суффикса `-base`.
  Суффикс остаётся внутренним делом хоста.

## Последствия

- Папка собирается в любом проекте без единой строчки настройки sass-loader.
  Ошибка `Undefined function tok-color` невозможна по построению.
- Числа рассыпались по компонентам: сменить шаг ритма разом больше нельзя —
  только `grep` по папке. Это осознанный размен переносимости на редактируемость;
  ритм у Тока не менялся ни разу с первой фазы.
- Смена темы стала целиком заботой хоста. Ток о ней не знает вовсе — в нём не
  осталось ни строчки, реагирующей на `light`/`dark`, кроме чтения переменных.
- Цепочка «палитра → `--v-tok-*-base` → `--v-tok-*`» на стенде длиннее прежней и
  рвётся молча: забытый в `tok-vars.scss` токен даёт невидимый элемент, а не
  ошибку сборки. Поэтому она целиком проверяется тестами `theme-vars.spec.js`
  и `demo-host.spec.js`.
- Запасные цвета графиков по-прежнему существуют в двух местах; совпадение копий
  проверяется тестом, а не глазами (`theme-parity.spec.js`).
