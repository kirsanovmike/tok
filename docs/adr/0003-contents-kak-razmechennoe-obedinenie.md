# ADR-0003. `contents[]` — размеченное объединение, вид графика есть `type`

**Дата:** 2026-08-12
**Статус:** принято

## Контекст

В `docs/api structure.txt` C#-класс `AssistantMessageResponse` содержал только `Reply` и `Workflow` — свойства `Contents` в нём **не было**, хотя JSON-пример его показывал и на нём держится весь рендеринг. Записи `PresentationPayload` ни к чему не были привязаны.

Дополнительно: `ChartPayloadData` имеет поле `Kind`, но JSON-пример показывает `"type": "circle"` — то есть вид графика приезжает как сам дискриминатор.

Заказчик подтвердил недостающее свойство:

```csharp
public AssistantContent[] Contents { get; set; } = default!;
```

и необходимость поддержки нескольких блоков в одном ответе.

## Решение

`contents` — массив блоков, дискриминатор — строковое поле `type`. Порядок блоков значим и сохраняется при рендеринге.

Виды графиков (`line`, `bar`, `circle`) — **самостоятельные значения `type`** наравне с `text`, `list`, `stat`, `table`, а не вложенное поле.

Диспетчер блоков при неизвестном `type` пропускает блок и логирует факт, но не роняет ленту.

## Последствия

- Не описанные пока «универсальные contents» и `source` добавляются без переделки рендерера.
- Устойчивость к опережающему развитию бэкенда: новый тип блока на старом фронтенде деградирует мягко.
- Каждый вид графика получает собственный компонент с осмысленной конфигурацией по умолчанию вместо одного «универсального» графика с ветвлениями.
