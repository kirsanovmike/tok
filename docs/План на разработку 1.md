# План на разработку 1 — переезд в `@tne-ui`

> **Для агента-исполнителя.** План самодостаточен: его выполняют в чистой сессии, не читая переписку, в которой он написан. Рекомендуемый саб-навык — `superpowers:subagent-driven-development` (или `superpowers:executing-plans`) — задача за задачей, по чекбоксам (`- [ ]`).

**Постановка:** `docs/Задача на доработку 1.md`. Этот файл отвечает на вопрос «как», постановка — на вопрос «что». **Расхождение между ними — дефект этого файла, а не повод отойти от постановки.**

**Предыдущие круги:** `docs/tasks/план на разработку 1.md`, `docs/tasks/план на доработку 1.md`, `docs/tasks/План на разработку2.md`, `docs/tasks/План на разработку3.md`. Решения оттуда действуют, если этот план их явно не отменяет — отменяемые перечислены в разделе «Отмена прежних решений».

**Цель.** Привести Ток к тому виду, в котором заказчик кладёт его в свою библиотеку: цвета приезжают из `@tne-ui/core` как `var(--v-tok-<токен>)` (без суффикса `-base`), функция `host-color()` исчезает, набор SCSS-функций/миксинов/переменных совпадает с тем, что заказчик уже положил в core, а компонент подключается **простым импортом в лейауте** — без плагина установки `installTok`. При этом Ток обязан оставаться работоспособным и в изолированном просмотре (Storybook), и на демо-стенде этого репозитория.

**Архитектура.** Три независимых по смыслу сдвига:

1. **Цвет.** Раньше цвета Тока вливались в тему Vuetify хоста и доставались как `--v-tok-surface-base` (суффикс дописывает парсер темы Vuetify 2). Теперь их объявляет `@tne-ui/core` обычными CSS-переменными `--v-tok-surface`. Ток перестаёт зависеть от темы Vuetify: `theme/tokens.js` остаётся **источником запасных значений** (графики amCharts и хосты без core), а новый модуль `theme/applyTokTheme.js` умеет разложить их в CSS-переменные там, где core нет.
2. **Стили.** `styles/_tokens.scss` становится копией контракта из `@tne-ui/core`: `tok-color()` без `-base`, `host-color()` удалена. Всё, чего в core нет (скругление шторки), переезжает внутрь того SFC, который этим пользуется.
3. **Установка.** `installTok` удаляется целиком. `MountingPortal` регистрируется локально в `Tok.vue` — `portal-vue` 2.1.7 экспортирует его именованным экспортом, и внутри он ссылается на `Portal`/`PortalTarget` напрямую, а не через глобальную регистрацию. Проверено по `node_modules/portal-vue/dist/portal-vue.esm.js:606` и `:562-575`.

Ни один слой не появляется и не исчезает: контракт API, стор, транспорт, голос и графики не трогаются вовсе.

**Стек.** Vue 2.6.14 (Options API), Vuetify 2.6.3 (после этого плана — **только на стенде**, компоненту она больше не нужна), SCSS, amCharts **4**.10.20, portal-vue 2.1.7, Jest + `@vue/test-utils` 1.x.

## Global Constraints

Действуют на все задачи и повторяются здесь, потому что исполнитель задачи видит только свой раздел.

- **Ни одного hex-литерала вне `src/Tok/theme/tokens.js`.** Цвета в SFC — только `tok-color(<токен>)`, в JS — только через `theme/tokens.js`. `linear-gradient(` допустим только в `src/Tok/styles/_tokens.scss`. Проверяет `tests/unit/tok-boundary.spec.js`.
- **Имя CSS-переменной цвета — `--v-tok-<ключ токена>`, без `-base`.** Ключи в `tokens.js` уже начинаются с `tok-`, поэтому имя переменной = `--v-` + ключ.
- **Наборы ключей `light` и `dark` в `tokens.js` обязаны совпадать** — `tests/unit/theme-parity.spec.js`. Ни одна задача этого плана новых цветов не вводит.
- **Цвет любого `<button>` — миксином `@include tok-button-color(<токен>)`**, а не `color:` напрямую: сбросы хоста перебивают одиночный класс.
- **Внутри `src/Tok/` — только относительные импорты.** Ни одного `@/…`: папка копируется в чужой проект, где алиаса `@` может не быть. В тестах (`tests/unit/**`) алиас `@/` разрешён и используется.
- **Тесты не лежат внутри `src/Tok/`** — только в `tests/unit/`.
- **Vue 2 Options API.** Никакого Composition API, никаких `<script setup>`.
- **amCharts именно 4.10.20.** API пятой версии неприменим целиком.
- **Стили не scoped, именование BEM с префиксом `tok-`.**
- **UI-копия на русском.** Комментарии в коде — на русском.
- Команды: `npm run test:unit`, `npm run lint`, `npm run lint:style`, `npm run serve`.
  Один файл тестов: `npx vue-cli-service test:unit --testPathPattern <path>`; один тест: `-t "<имя>"`.
  Все скрипты обёрнуты в `cross-env NODE_OPTIONS=--openssl-legacy-provider` — вызывать только через `npm run` / `npx vue-cli-service`.
- **jsdom не считает layout.** Пиксели, тени и отступы автотестами не проверяются: вёрстка проверяется grep-ом по исходнику (так уже сделано в `tok-shell.spec.js`, `tok-loader.spec.js`, `tok-composer.spec.js`), остальное — глазами по блоку «Визуальная проверка» в каждой задаче.
- **Коммит в конце каждой задачи**, сообщение на русском, с завершающей строкой
  `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`.

### Задача 1: Запасные переменные `--v-tok-*` и их объявление на стенде

Закрывает строки **1–5** постановки со стороны «а откуда переменные возьмутся там, где `@tne-ui/core` нет».

**Файлы:**
- Создать: `src/Tok/theme/applyTokTheme.js`
- Изменить: `src/Tok/index.js`
- Изменить: `src/demo/App.vue`
- Тест: `tests/unit/theme-vars.spec.js` (создать), `tests/unit/demo-host.spec.js` (дополнить)

**Интерфейсы:**
- Потребляет: `src/Tok/theme/tokens.js` — `export default { light, dark }`, плоские объекты `{ 'tok-surface': '#FFFFFF', … }`.
- Отдаёт (на это опираются задачи 2, 4, 5):
  - `tokThemeCssVars(mode: 'light' | 'dark'): Record<string, string>` — ключи вида `--v-tok-surface`;
  - `hasHostTokTheme(target?: Element): boolean` — объявил ли переменные кто-то снаружи;
  - `applyTokTheme(mode: 'light' | 'dark', options?: { target?: Element, force?: boolean }): boolean` — записывает переменные инлайново, возвращает «записал ли».

**Диагноз.** Сейчас `--v-tok-*-base` печатает Vuetify: демо-стенд вливает `tokThemeTokens` в `theme.themes` (`src/demo/theme/index.js`), а `options.customProperties: true` заставляет Vuetify объявить их в `:root`. После задачи 2 компонент будет читать переменные **без** суффикса, и Vuetify их не даст: он суффикс дописывает всегда. В Трансфере переменные объявит `@tne-ui/core`, а стенду и изолированному просмотру нужен свой источник — им и станет `applyTokTheme`.

Защита от перекрытия обязательна: если хост переменные уже объявил, писать поверх нельзя — инлайновый стиль на `<html>` победит правила core и заморозит тему. Отличать «уже объявил хост» от «объявили мы сами на прошлом переключении темы» нужно по инлайновому стилю: `getComputedStyle` видит и его тоже, поэтому без этой развилки вторая смена темы молча перестала бы работать.

- [x] **Шаг 3: Написать модуль**

Создать `src/Tok/theme/applyTokTheme.js`:

```js
/**
 * Запасной источник CSS-переменных Тока.
 *
 * Штатно `--v-tok-*` объявляет `@tne-ui/core` — Ток их только читает
 * (`tok-color()` в `styles/_tokens.scss`). Но компонент обязан оставаться
 * смотрибельным и там, где библиотеки нет: демо-стенд этого репозитория,
 * изолированный просмотр в Storybook, страница-песочница. Для таких мест
 * здесь лежит функция, раскладывающая значения из `theme/tokens.js`
 * в те же самые переменные.
 *
 * Вызывать это в Трансфере не нужно и вредно: инлайновый стиль на элементе
 * сильнее правил `@tne-ui/core`, и тема перестала бы переключаться. Поэтому
 * по умолчанию функция сначала проверяет, не объявлены ли переменные уже.
 */
import tokens from './tokens';

/** Префикс переменных темы. Ключи токенов уже начинаются с `tok-`. */
export const TOK_CSS_PREFIX = '--v-';

/**
 * По какому токену проверяется «переменные уже объявлены».
 * Фон панели есть в любой сборке темы — если нет его, нет ничего.
 */
const PROBE_TOKEN = 'tok-surface';

function probeName() {
  return `${TOK_CSS_PREFIX}${PROBE_TOKEN}`;
}

/**
 * Значения темы в виде «имя CSS-переменной → цвет».
 *
 * @param {'light'|'dark'} mode
 * @returns {Object<string, string>}
 */
export function tokThemeCssVars(mode) {
  const source = tokens[mode === 'dark' ? 'dark' : 'light'];

  return Object.keys(source).reduce((acc, name) => {
    acc[`${TOK_CSS_PREFIX}${name}`] = source[name];
    return acc;
  }, {});
}

/**
 * Объявил ли переменные Тока кто-то снаружи (обычно `@tne-ui/core`).
 *
 * @param {Element|null} target
 * @returns {boolean}
 */
export function hasHostTokTheme(target) {
  if (!target || typeof window === 'undefined' || typeof window.getComputedStyle !== 'function') {
    return false;
  }

  try {
    return window.getComputedStyle(target).getPropertyValue(probeName()).trim() !== '';
  } catch (e) {
    return false;
  }
}

/**
 * Переменные, записанные инлайново нами же на прошлом вызове.
 *
 * Без этой проверки вторая смена темы отвалилась бы: `getComputedStyle`
 * видит и инлайновый стиль, поэтому `hasHostTokTheme` после первого вызова
 * всегда правдив.
 */
function ownsTokTheme(target) {
  return Boolean(target.style) && target.style.getPropertyValue(probeName()).trim() !== '';
}

/**
 * Разложить тему Тока в CSS-переменные элемента.
 *
 * @param {'light'|'dark'} mode тема хоста
 * @param {{ target?: Element, force?: boolean }} [options]
 *   `target` — куда писать, по умолчанию `<html>`;
 *   `force` — писать даже поверх переменных хоста.
 * @returns {boolean} записали ли переменные
 */
export function applyTokTheme(mode, options) {
  const settings = options || {};
  const target =
    settings.target || (typeof document !== 'undefined' ? document.documentElement : null);

  if (!target || !target.style) return false;
  if (!settings.force && !ownsTokTheme(target) && hasHostTokTheme(target)) return false;

  const vars = tokThemeCssVars(mode);
  Object.keys(vars).forEach((name) => target.style.setProperty(name, vars[name]));

  return true;
}

export default applyTokTheme;
```

   тянется из библиотеки во все SPA. Плагину установки в такой схеме взяться
   неоткуда: лейаут импортирует компонент, а не настраивает конструктор Vue.

## Решение

- `tok-color($token)` возвращает `var(--v-tok-#{$token})`. Функции `host-color()`
  в компоненте нет: базовые цвета хоста ему не нужны, а демо-стенду она оставлена
  в `src/demo/styles/_host.scss`.
- Набор функций, миксинов и SCSS-переменных Тока живёт в `@tne-ui/core`; копия
  в `src/Tok/styles/_tokens.scss` держится байт в байт и нужна там, где core нет.
  Скругление шторки в контракт не входит — оно объявлено в `TokPanel.vue`.
- `installTok` удалён. `MountingPortal` регистрируется локально в `Tok.vue`.
  Импорт по умолчанию из `index.js` отдаёт сам компонент.
- `theme/tokens.js` остаётся источником истины по значениям цвета: из него
  красится amCharts (SVG из JS не понимает `var(…)`) и из него же
  `theme/applyTokTheme.js` раскладывает переменные там, где `@tne-ui/core` нет.
  Поверх объявлений библиотеки `applyTokTheme` не пишет.

## Последствия

- Ток больше не зависит от темы Vuetify вовсе. Vuetify остаётся зависимостью
  только демо-стенда.
- Значения цветов существуют в двух местах: в `@tne-ui/core` и в `theme/tokens.js`.
  Расхождение возможно и ловится только глазами — источником истины считается core,
  `tokens.js` правится следом.
- Схема установки у хоста упрощается до одной строки импорта; забыть шаг установки
  больше нельзя.
- Функции и миксины контракта должны быть в области видимости каждого SFC.
  В `@tne-ui` это обеспечено самой библиотекой; копия `styles/_tokens.scss`
  в папке нужна только там, где core нет.

## Что осталось на стороне заказчика

Эти пункты план закрыть не может — они за границей репозитория. Их нужно проверить при первой сборке в библиотеке.

1. **Полнота набора переменных.** В `@tne-ui/core` должны быть объявлены все ключи из `src/Tok/theme/tokens.js` — их 25 в каждой теме. Недостающая переменная сборку не сломает, а тихо съест цвет: `var(--v-tok-…)` без значения и без запасного просто ничего не вернёт.
2. **`$tok-panel-radius`.** План объявляет его в `TokPanel.vue`, потому что в перечне из постановки его нет. Если заказчик решит, что скругление шторки должно жить в core, — переменную нужно перенести туда и убрать локальное объявление вместе с проверкой в `tok-boundary.spec.js`.
3. **ffmpeg.wasm для голосового ввода.** Четыре файла должны отдаваться статикой по пути `config.ffmpegBaseUrl` (ADR-0007), иначе голос нужно выключить флагом `voiceEnabled: false`.

Импорт `.scss` в `main.js` даёт CSS, но не функции и миксины: они видны только там, где партиал подключён `css.loaderOptions.scss.additionalData` (Vue CLI) / `css.preprocessorOptions.scss.additionalData` (vite) либо `@import`-ом внутри самого блока `<style>`.
