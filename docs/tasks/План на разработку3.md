**Цель.** Развернуть реплики пользователя вправо; убрать из ленты жирный дефолтный скроллбар и прижать тонкий к правому краю панели; перестроить композер по двум референсам ChatGPT (однострочное и многострочное состояния, кнопка очистки в нижнем ряду слева); замедлить смену фраз лоадера в полтора раза; развести подпись и холст графика; сделать шторку тянущейся по ширине — от новой минимальной 520px до полного экрана.

**Архитектура.** Все семь пунктов — правки существующих файлов плюс два новых модуля под пункт 7: чистая арифметика ширины (`services/utils/panelWidth.js`) и ручка перетаскивания (`SubComponents/TokResizeHandle.vue`). Ни один слой не появляется и не исчезает; контракт, стор и транспорт не трогаются вовсе. Логика, которую jsdom проверить не может (пиксели), выносится в чистые функции — так же, как это уже сделано в `services/utils/autoGrow.js`.

**Стек.** Vue 2.6.14 (Options API), Vuetify 2.6.3, SCSS, amCharts **4**.10.20, Jest + `@vue/test-utils` 1.x.

## Global Constraints

Действуют на все задачи и повторяются здесь, потому что исполнитель задачи видит только свой раздел.

- **Ни одного hex-литерала вне `src/Tok/theme/tokens.js`.** Цвета в компонентах — только через `tok-color(<токен>)`. `linear-gradient(` допустим только в `src/Tok/styles/_tokens.scss`. Проверяет `tests/unit/tok-boundary.spec.js`.
- **Наборы ключей `light` и `dark` в `tokens.js` обязаны совпадать** — `tests/unit/theme-parity.spec.js`. Ни одна задача этого плана новых цветов не вводит: всё, что нужно, уже есть (`border-strong`, `text-muted`, `surface`, `accent`).
- **Цвет любого `<button>` — миксином `@include tok-button-color(<токен>)`**, а не `color:` напрямую: сбросы хоста перебивают одиночный класс.
- **Vue 2 Options API.** Никакого Composition API, никаких `<script setup>`.
- **amCharts именно 4.10.20.** API пятой версии неприменим целиком.
- **Отступы и скругления — из SCSS-переменных** `$tok-space-*`, `$tok-radius-*` (`src/Tok/styles/_tokens.scss`), они подключаются во все SFC автоматически через `vue.config.js`.
- **Стили не scoped, именование BEM с префиксом `tok-`.**
- **Внутри `src/Tok/` — только относительные импорты.** Ни одного `@/…`: папка копируется в чужой проект, где алиаса `@` может не быть. В тестах (`tests/unit/**`) алиас `@/` разрешён и используется.
- **Тесты не лежат внутри `src/Tok/`** — только в `tests/unit/`.
- **Уважать `prefers-reduced-motion`** во всех анимациях и переходах.
- **UI-копия на русском.**
- Команды: `npm run test:unit`, `npm run lint`, `npm run lint:style`, `npm run serve`.
  Один файл тестов: `npx vue-cli-service test:unit --testPathPattern <path>`; один тест: `-t "<имя>"`.
  Все скрипты обёрнуты в `cross-env NODE_OPTIONS=--openssl-legacy-provider` — вызывать только через `npm run` / `npx vue-cli-service`.
- **jsdom не считает layout.** Пиксели, тени, отступы, вращение и реальная прокрутка автотестами не проверяются: арифметика проверяется на чистых функциях, вёрстка — grep-ом по исходнику (так уже сделано в `tok-loader.spec.js` и `tok-composer.spec.js`), остальное — глазами по блоку «Визуальная проверка» в каждой задаче.
- **Коммит в конце каждой задачи**, сообщение на русском, с завершающей строкой
  `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`.

### Задача 2: Тонкий скролл ленты, прижатый к правому краю

Закрывает пункт **2** постановки: «скролл общего чата аккуратно прижат до конца вправо и тоньше в два раза и менее яркий».

**Файлы:**
- Изменить: `src/Tok/styles/_tokens.scss`, `src/Tok/SubComponents/TokPanel.vue`, `src/Tok/SubComponents/TokMessageList.vue`, `src/Tok/SubComponents/TokEmptyState.vue`
- Тест: `tests/unit/tok-shell.spec.js`

**Интерфейсы:**
- Производит: SCSS-переменную `$tok-scrollbar-size` и миксин `@include tok-thin-scrollbar($size)` в `src/Tok/styles/_tokens.scss`. Миксин потребляет задача 3 — он же красит скролл внутри `textarea` композера.
- Потребляет: ничего.

**Диагноз.** Прокручивается `.tok-feed` (`TokMessageList.vue`), а горизонтальные отступы заданы её родителю — `.tok-panel__body { padding: 0 $tok-space-lg; }` (`TokPanel.vue:337`). Полоса прокрутки рисуется по правому краю **прокручиваемого** элемента, то есть в 24px от края панели — она и «висит в воздухе». Отсюда решение: отступы переезжают с родителя на самих детей (`.tok-feed` и `.tok-empty`), прокручиваемый элемент дотягивается до края панели, и полоса встаёт вплотную к нему.

Толщина и цвет — своим правилом: дефолтный скроллбар WebKit ~12–15px и тёмно-серый. Ставим 6px и `border-strong` — это ровно «в два раза тоньше и менее яркий». Firefox настраивается парой `scrollbar-width` / `scrollbar-color`, WebKit — псевдоэлементами; нужны оба, миксин закрывает оба.

**Про `box-sizing`.** У `.tok-feed` есть `height: 100%`; добавляя ей отступы, обязательно ставим `box-sizing: border-box` явно. Полагаться на сброс хоста нельзя: папка едет в чужой проект, где сброса может не быть, и лента вылезла бы за пределы панели ровно на величину отступов.

### Задача 3: Композер по двум референсам

Закрывает пункты **3** и **4** постановки: кнопка очистки при большом тексте уходит вниз, к микрофону и отправке, но слева; поле ввода и его прокрутка — по референсам ChatGPT.

**Файлы:**
- Изменить: `src/Tok/services/utils/autoGrow.js`, `src/Tok/SubComponents/TokComposer.vue`
- Тест: `tests/unit/tok-composer.spec.js`

**Интерфейсы:**
- Потребляет: миксин `tok-thin-scrollbar` из задачи 2 (`src/Tok/styles/_tokens.scss`).
- Производит: `isMultiline(scrollHeight, min?) → boolean` в `src/Tok/services/utils/autoGrow.js`; константа `COMPOSER_MAX_HEIGHT` меняет значение со 128 на 160 (её уже импортируют тесты).

**Диагноз.** Сейчас `.tok-composer__field` — одна flex-строка: крестик (`order: -1`), поле, микрофон, отправка. Пока текста мало, это ровно референс «когда нет текста». Когда текст вырос, референс требует другого: поле занимает всю ширину сверху, а все три кнопки уезжают в нижний ряд — очистка слева, микрофон и отправка справа. Прежнее `align-self: center` у крестика — решение задачи «Доработок 2», и постановка 3 его отменяет: тот же крестик теперь обязан быть **прижат к низу вместе с остальными кнопками**.

Менять DOM между состояниями не нужно и вредно (перемонтирование `textarea` теряет каретку и фокус). Обе раскладки даёт **CSS Grid** на одном и том же порядке детей: `clear → input → mic → send`. Различие — одна строка `grid-template-areas`.

Состояние «многострочно» определяется измерением, а не длиной строки: перенос зависит от ширины панели, шрифта хоста и переносов, введённых человеком. Измерение живёт в `resize()`, а решение по измеренному числу — в чистой функции `isMultiline`, потому что `scrollHeight` в jsdom всегда 0 и проверить это внутри компонента невозможно.

**Про потолок высоты.** Референс «когда много текста» показывает поле высотой около восьми строк. Поднимаем `COMPOSER_MAX_HEIGHT` со 128 (шесть строк) до 160 (восемь). Выше нельзя: композер вместе с кнопками и отступами занял бы больше четверти панели и съел ленту.

```js
/**
 * Переросло ли содержимое одну строку.
 *
 * От этого зависит раскладка композера: пока строка одна, кнопки стоят в том же
 * ряду, что и поле; как только текст перенёсся — уезжают в нижний ряд

 * Незамеренное поле (jsdom, скрытый контейнер) многострочным не считается:
 * раскладка не имеет права прыгать на пустом измерении.
 */
export function isMultiline(scrollHeight, min) {
  const floor = typeof min === 'number' ? min : COMPOSER_MIN_HEIGHT;
  return Number.isFinite(scrollHeight) && scrollHeight > floor;
}
```

### Задача 6: Шторка тянется по ширине

Закрывает пункт **7** постановки: «сделать боковую панель ресайзбл, вот текущая ширина — мин и можно ещё раскрыть во весь экран. И кстати текущую ширину увеличить на 30–40 пикселей, чтобы чуть побольше стала».

**Файлы:**
- Создать: `src/Tok/services/utils/panelWidth.js`, `src/Tok/SubComponents/TokResizeHandle.vue`
- Изменить: `src/Tok/styles/_tokens.scss`, `src/Tok/SubComponents/TokPanel.vue`
- Тест: `tests/unit/tok-shell.spec.js`

**Интерфейсы:**
- Производит (`services/utils/panelWidth.js`):
  - `PANEL_MIN_WIDTH: number` — 520;
  - `PANEL_WIDTH_STEP: number` — 24, шаг клавиатуры;
  - `PANEL_RESIZE_MIN_VIEWPORT: number` — 600, ниже этой ширины окна ручки нет;
  - `panelMaxWidth(viewportWidth: number) → number`;
  - `clampPanelWidth(width: number, viewportWidth: number) → number` (целое);
  - `widthFromPointerX(clientX: number, viewportWidth: number) → number`;
  - `isPanelResizable(viewportWidth: number) → boolean`.
- Производит (`SubComponents/TokResizeHandle.vue`): компонент `TokResizeHandle` с пропами `width: Number`, `min: Number`, `max: Number` и событиями `resize` (новая ширина в пикселях), `dragstart`, `dragend`.
- Производит SCSS-переменную `$tok-panel-min-width: 520px` — она обязана совпадать с `PANEL_MIN_WIDTH`, совпадение проверяет тест.

**Решения, принятые здесь.**

1. **520px** — это 480 + 40, верхняя граница просьбы «на 30–40 пикселей», и одновременно минимум ширины.
2. **Ширина не сохраняется между сеансами.** Она живёт в `data` панели, а панель не размонтируется при закрытии — значит, ширина держится всю сессию, что и требуется. `localStorage` не трогаем: там лежит переписка с TTL и версионированным ключом (ADR-0004), и класть туда настройку интерфейса — значит расширять хранилище персональных данных ради 3 байт.
3. **Планшетный медиазапрос `max-width: 959px` снимается.** Он задавал `60vw` с минимумом 420px — прямое противоречие новому минимуму 520. На окне 960–1200px панель 520px занимает половину экрана, и человек сам растянет её ручкой.
4. **Ниже 600px ручки нет.** Там панель занимает `100vw`, тянуть нечего. Если окно сузили уже после перетаскивания, инлайновая ширина снимается — иначе она перебила бы медиазапрос (инлайн-стиль сильнее любого правила таблицы).
5. **Арифметика — в чистом модуле.** По той же причине, что и `autoGrow.js`: jsdom не считает layout, и проверять расчёт ширины внутри компонента бессмысленно.
6. **Доступность.** Ручка — `role="separator"` с `tabindex="0"`, `aria-valuenow/min/max`: это стандартный паттерн «window splitter». Она попадает в ловушку фокуса панели автоматически — `getFocusableElements` отбирает в том числе `[tabindex]:not([tabindex="-1"])`. Стрелки меняют ширину на 24px, Home возвращает минимум, End раскрывает во весь экран, двойной клик — тоже минимум.

Создать `src/Tok/services/utils/panelWidth.js`:

```js
/**
 * Ширина шторки Тока.
 *
 * Отдельный модуль по той же причине, что и `autoGrow.js`: jsdom не считает
 * layout, и проверить арифметику перетаскивания внутри компонента невозможно.
 * Здесь она проверяется честно, а компоненту остаётся чтение события указателя
 * и присвоение стиля.
 *
 * Пиксели связаны с вёрсткой `TokPanel.vue`: `PANEL_MIN_WIDTH` обязан совпадать
 * со SCSS-переменной `$tok-panel-min-width` (`styles/_tokens.scss`) — совпадение
 * проверяет тест «минимальная ширина одна и та же в SCSS и в JS».
 */

/**
 * Стартовая и минимальная ширина панели. Постановка «Доработки 3», пункт 7:
 * прежние 480px просили увеличить на 30–40 пикселей, и эта же ширина объявлена
 * минимальной — уже неё панель не тянется.
 */
export const PANEL_MIN_WIDTH = 520;

/** Шаг изменения ширины с клавиатуры. */
export const PANEL_WIDTH_STEP = 24;

/**
 * Ниже этой ширины окна панель занимает его целиком (медиазапрос 599px плюс
 * запас): тянуть нечего, и ручка только мешала бы попадать в ленту пальцем.
 */
export const PANEL_RESIZE_MIN_VIEWPORT = 600;

/** Ширина окна, с подстраховкой от `undefined` при рендере без окна. */
function viewportOf(viewportWidth) {
  return Number.isFinite(viewportWidth) && viewportWidth > 0 ? viewportWidth : PANEL_MIN_WIDTH;
}

/** Потолок: «во весь экран», но не уже минимума. */
export function panelMaxWidth(viewportWidth) {
  return Math.max(viewportOf(viewportWidth), PANEL_MIN_WIDTH);
}

/**
 * Ширина, зажатая между минимумом и шириной окна.
 * Округление обязательно: дробная ширина даёт полупиксельную границу панели,
 * и правый край перестаёт быть строгой линией.
 */
export function clampPanelWidth(width, viewportWidth) {
  const measured = Number.isFinite(width) ? width : PANEL_MIN_WIDTH;
  const bounded = Math.min(Math.max(measured, PANEL_MIN_WIDTH), panelMaxWidth(viewportWidth));
  return Math.round(bounded);
}

/**
 * Ширина по горизонтальному положению указателя. Панель прижата к правому краю
 * окна, поэтому ширина — это расстояние от указателя до этого края.
 */
export function widthFromPointerX(clientX, viewportWidth) {
  const x = Number.isFinite(clientX) ? clientX : 0;
  return clampPanelWidth(viewportOf(viewportWidth) - x, viewportWidth);
}

  return viewportOf(viewportWidth) > PANEL_RESIZE_MIN_VIEWPORT;
}
```

```vue
  <div
    class="tok-resize-handle"
    role="separator"
    aria-orientation="vertical"
    aria-label="Ширина панели"
    :aria-valuenow="width"
    :aria-valuemin="min"
    :aria-valuemax="max"
    tabindex="0"
    @pointerdown="onPointerDown"
    @keydown="onKeydown"
    @dblclick="$emit('resize', min)"
  />
</template>

<script>
/**
 * Ручка изменения ширины шторки: невидимая полоса вдоль левого края панели.
 *
 * Ручка не владеет шириной — она сообщает наверх желаемую и ничего не решает
 * сама: зажать значение между минимумом и шириной окна обязана панель, иначе
 * ограничение оказалось бы в двух местах.
 *
 * Слушатели перетаскивания вешаются на `window`, а не на саму ручку: указатель
 * во время движения почти всегда оказывается за её пределами.
 *
 * Автор: Кирсанов Михаил
 * @displayName Tok Resize Handle
 * @event resize — желаемая ширина панели в пикселях
 * @event dragstart — начало перетаскивания
 * @event dragend — конец перетаскивания
 */

// services
import { PANEL_WIDTH_STEP, panelMaxWidth, widthFromPointerX } from '../services/utils/panelWidth';

export default {
  name: 'TokResizeHandle',

  props: {
    /* Текущая ширина панели в пикселях — для скринридера и для шага клавиатуры. */
    width: {
      type: Number,
      required: true,
    },
    /* Минимальная ширина панели. */
    min: {
      type: Number,
      required: true,
    },
    /* Максимальная ширина панели: весь экран. */
    max: {
      type: Number,
      required: true,
    },
  },

  beforeDestroy() {
    // Панель могли закрыть прямо во время перетаскивания — слушатели на window
    // не имеют права пережить компонент.
    this.stopDrag();
  },

  methods: {
    onPointerDown(event) {
      // Тянут именно ручку: выделение текста в панели и прокрутка страницы на
      // тач-устройстве во время перетаскивания только мешают.
      event.preventDefault();

      const element = this.$el;
      if (element && element.setPointerCapture && event.pointerId !== undefined) {
        try {
          element.setPointerCapture(event.pointerId);
        } catch (e) {
          // Указатель уже отпущен — перетаскивание всё равно отработает по window.
        }
      }

      window.addEventListener('pointermove', this.onPointerMove);
      window.addEventListener('pointerup', this.onPointerUp);
      window.addEventListener('pointercancel', this.onPointerUp);
      this.$emit('dragstart');
    },

    onPointerMove(event) {
      this.$emit('resize', widthFromPointerX(event.clientX, window.innerWidth));
    },

    onPointerUp() {
      this.stopDrag();
      this.$emit('dragend');
    },

    /** Снять слушатели перетаскивания. Вызывается и при уничтожении компонента. */
    stopDrag() {
      window.removeEventListener('pointermove', this.onPointerMove);
      window.removeEventListener('pointerup', this.onPointerUp);
      window.removeEventListener('pointercancel', this.onPointerUp);
    },

    /**
     * Клавиатура: стрелка влево расширяет панель (край едет влево), вправо —
     * сужает, Home возвращает минимум, End раскрывает во весь экран.
     */
    onKeydown(event) {
      const moves = {
        ArrowLeft: this.width + PANEL_WIDTH_STEP,
        ArrowRight: this.width - PANEL_WIDTH_STEP,
        Home: this.min,
        End: panelMaxWidth(typeof window === 'undefined' ? 0 : window.innerWidth),
      };

      const next = moves[event.key];
      if (next === undefined) return;

      // Стрелки внутри панели иначе прокрутили бы ленту.
      event.preventDefault();
      this.$emit('resize', next);
    },
  },
};
</script>
```

## Чего в этом плане намеренно нет

- **Сохранения ширины между сеансами.** Постановка просит ресайз, а не запоминание; `localStorage` Тока хранит переписку с TTL и версионированным ключом (ADR-0004), и настройка интерфейса там — лишняя сущность. Ширина держится всю сессию, потому что панель не размонтируется.
- **Ресайза по вертикали и перетаскивания панели за заголовок.** Шторка прижата к правому краю по постановке первого круга; менять это никто не просил.
- **Нового ADR.** Ни одно решение этого круга не меняет архитектуру: два новых модуля ложатся в существующие правила раскладки (ADR-0008).
- **Правки самой постановки** `docs/Доработки и корректировки 3.txt`: отметки о выполнении ведутся чекбоксами этого файла.
