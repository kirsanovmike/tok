# CONTEXT — Ток

Единый язык проекта. Термины отсюда используются в коде, именах компонентов, сообщениях коммитов и заголовках задач. Синонимы, помеченные «не говорим», не употребляем.

## Продукт

**Трансфера** — энергосбытовая платформа, в которую встраивается Ток. Хост-приложение. Не говорим «основное приложение», «портал».

**Ток** — компонент AI-ассистента внутри Трансферы. Именно компонент, не отдельное приложение. Латиницей в коде — `tok`.

**Панель** (panel) — выезжающая справа шторка с чатом. Левые углы скруглены, правый край прямой. Не говорим «модалка», «дровер», «попап».

**Точка входа** (entry point) — плавающая кнопка со звёздочками в правом нижнем углу хоста, открывающая панель.

**Демо-хост** (demo host) — упрощённый дашборд Трансферы в этом репозитории, нужный только чтобы проверять Ток. Не переносится в Трансферу.

## Диалог

**Беседа** (conversation) — вся переписка, объединённая одним `conversationId`. Сервер выдаёт идентификатор на первом ответе; в первом запросе он `null`.

**Сообщение** (message) — одна реплика: либо пользователя, либо ассистента.

**Ответ** (reply) — часть ответа сервера с текстом и `kind`. `kind` ∈ `clarification | confirmation | success | fallback | error`.

**Рабочий процесс** (workflow) — состояние многошагового автомата: `status` ∈ `collecting | confirming | executing | completed | fallback | informational | forbidden`, плюс `intent`, `domain`, `awaitingConfirmation`. Ток обязан отражать состояние, а не рисовать каждый ответ одинаково.

**Шаг подтверждения** — состояние `awaitingConfirmation: true`, при котором пользователю показываются «Подтвердить» / «Отменить».

**Чип-подсказка** (suggestion chip) — готовый вопрос на пустом экране. Это call to action: после нажатия ассистент уточняет недостающие параметры.

## Содержимое ответа

**Блок** (content) — один элемент массива `contents[]`. Дискриминатор — строковое поле `type`. В одном ответе допустимо несколько блоков, порядок значим.

**Диспетчер блоков** (content dispatcher) — компонент, выбирающий по `type` дочерний компонент. Неизвестный `type` пропускает, но не роняет ленту.

Типы блоков: `text`, `list`, `stat`, `table`, а также типы графиков — `line`, `bar`, `circle`. Вид графика является самостоятельным значением `type`, а не вложенным полем.

**Реестр блоков** (content registry) — соответствие `type` → компонент. Единственное место, где добавляется новый тип блока.

**Ряд** (series) — одна линия или один набор столбцов на графике. У ряда есть имя и точки «категория — значение». Легенда показывается, когда рядов больше одного.

**Текстовое представление ответа** — то, что уходит в буфер обмена по кнопке копирования: вводная фраза плюс все блоки в порядке показа. Таблица представляется колонками через табуляцию, чтобы вставляться в Excel.

## Голос

**Голосовой ввод** (voice input) — запись вопроса с микрофона вместо набора текстом.

**Запись** (recording) — состояние, в котором строка ввода уступает место полосе с отменой, таймером и остановкой.

**Расшифровка** (transcription) — превращение записи в текст на стороне сервера. Ответ — `{ "text": "..." }`. Результат **подставляется** в композер, а не отправляется: последнее слово за человеком. Не говорим «распознавание речи», «STT».

**Кодирование** (encoding) — превращение записи браузера в MP3 перед отправкой. Скрыто за `encodeToMp3(blob)`.

## Хранение

**Хранилище беседы** (conversation storage) — `localStorage` под версионированным ключом `tok:conversation:v1`. Хранит только сообщения и `conversationId`.

**Пространство имён** (namespace) — идентификатор пользователя из хоста в составе ключа. Сменился пользователь — прошлая переписка ему не покажется.

**TTL** — один **календарный** месяц с момента сообщения. Просроченные удаляются при инициализации.

## Предметная область ответов

**Договор** (contract) — единица, по которой задаётся вопрос. Вместе с периодом образует обязательные параметры любого запроса к данным.

**Период** — пара дат `sDate` / `eDate`. Для процентной динамики — две пары.

**Тариф** (`cost`), **объём потребления** (`volume`), **стоимость** (`price`) — три анализируемых параметра. Каждый отвечается в одном из трёх форматов: значение за период, график динамики, процент изменения период к периоду.

## Техническое

**Переносимая папка** — `src/Tok/`. Копируется в Трансферу и в общую библиотеку компонентов без правок. Не импортирует ничего из `src/demo/`, не содержит тестов и не пользуется алиасом `@` — только относительными путями.

**Родительский компонент** — `Tok.vue` в корне папки. Единственное, что хост вставляет в разметку; собирает конфигурацию, транспорт, стор и голосовой конвейер и раздаёт их вниз через `provide`.

**Дочерние компоненты** — `SubComponents/`, плоским списком, без вложенных папок под иконки и блоки контента. Соответствие «тип блока → компонент» живёт в `services/contentRegistry.js`.

**Сервисы** — `services/`: логика и данные без вёрстки, ни одного `.vue`. Внутри — `api/`, `store/`, `charts/`, `voice/`, `constants/`, `utils/` и витрина `services/index.js`, из которой берёт зависимости родительский компонент.

**Слой-обёртка** — тонкая прослойка над примитивами Vuetify в тех местах, где в Трансфере стоял бы компонент `@tne-ui`. Точка будущей замены.

**Токен темы** — ключ палитры Vuetify. Цвета задаются только через них; hex в компонентах запрещён.

**Мок-слой** — фикстуры ответов ассистента, покрывающие комбинации `kind` × `status` × типы блоков. Заменяется реальным транспортом через конфигурацию.
